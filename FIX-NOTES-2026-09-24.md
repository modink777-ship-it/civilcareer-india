## 1 · CRITICAL: Private jobs not displaying — FIXED

**Root causes found (all fixed):**

1. **`timeAgo()` was never defined** but was called by the job-card renderer → `ReferenceError` killed rendering after the first card was built. Replaced by a real `timeAgo()` (and `ago()` in v8 already existed for government pages).
2. **Exact sector equality** — `(j.sector||'Private')==='Private'` dropped every record whose sector was `private`, `PRIVATE`, `Private Sector`, `MNC`, `private-sector`, `company` or empty. A Node simulation proved only 1 of 5 sample records survived. Fixed with **`sectorOf(j)`** in app.js: `/gov|public sector|psu|sarkari/ → Government`, `/private|mnc|company|corporate/ → Private`, **empty/other → Private (records never vanish)**. All private-pipeline code (`activePrivate()`, `renderPrivate`, home stats, For You, search) now uses it via the `isGovJob()` wrapper or its own fallback.
3. **app.js `renderPrivate` forced category tiles** before the list; v8's override is the live renderer and now runs a single honest filter chain.
4. **Location-scope over-filtering** — State-wise / City-wise no longer drop jobs whose optional location fields are missing (an all-India job stays visible in every scope; state/city name matching falls back to `locations[]` text).

**Honest empty states:** if valid private jobs exist but filters return zero → "No jobs match these filters — N private jobs exist but none pass the selected filters. Remove one filter or clear all." If the source truly has zero private jobs → "No private jobs are currently available." The count is always rendered.

**Verified:** Node simulation of the full normalization → `sectorOf` → `activePrivate` → filter chain pipeline passes (8/8 messy-sector records classify correctly; quick filters, salary ×12 and scope rules behave).

Discovery results **always render**; duplicates are labelled ("Marked as possible duplicates") and summarized — never silently hidden.
